# Backend Data Contract Draft

This document defines the shared data model for backend and frontend development.

## Core entities

The following entities are persisted in PostgreSQL:

- User
- Trip
- TripDay
- POI
- PlanItem

Route data is generated by the Route Planning module and is not persisted.

## Relationships

- One User has many Trips.
- One Trip has many TripDays.
- One TripDay has many PlanItems.
- One POI can be referenced by many PlanItems.

## Core fields

| Field | Java type | Required | Notes |
|---|---|---:|---|
| id | Long | Yes | Generated database ID |
| email | String | Yes | Must be unique |
| name | String | Yes | User display name |
| passwordHash | String | Yes | Internal authentication field; never return to the frontend |
| createdAt | LocalDateTime | Yes | Generated when the user is created |
| updatedAt | LocalDateTime | Yes | Updated automatically |

### TripDay

The Java entity is named `TripDay` to distinguish it from general date values. API data may refer to it as `Day`.

| Field | Java type | Required | Notes |
|---|---|---:|---|
| id | Long | Yes | Generated database ID |
| tripId | Long | Yes | Parent trip |
| date | LocalDate | Yes | Calendar date |
| dayIndex | Integer | Yes | Zero-based day position; the first day is 0 |

The current model supports `dayIndex` values from 0 through 14.

A trip cannot contain two TripDays with the same `dayIndex`.

### PlanItem

| Shared field | Entity representation | Required | Notes |
|---|---|---:|---|
| id | id | Yes | Generated database ID |
| dayId | tripDay | Yes | Stored through the `trip_day_id` foreign key |
| poiId | poi | Yes | Stored through the `poi_id` foreign key |
| order | visitOrder | Yes | Visit position; starts from 1 |
| scheduledTime | scheduledTime | No | Planned visit time |
| reminderTime | reminderMinutesBefore | No | Currently stored as minutes before the scheduled time |
| durationMinutes | durationMinutes | No | Estimated visit duration |
| note | note | No | User note |

The Entity uses `visitOrder` instead of `order` because `ORDER` is an SQL keyword.

The current reminder model stores an integer number of minutes before `scheduledTime`. The team should confirm whether the shared API field should be named `reminderTime` or `reminderMinutesBefore`.

## Shared ID field names

Use the following names in API requests and responses:

- userId
- tripId
- dayId
- poiId
- planItemId

Use `poiId`, not `poiID`.

## Date and time formats

- Date: `YYYY-MM-DD`
- Time: `HH:mm`
- Date and time: ISO 8601 format

2026-09-20
09:30
